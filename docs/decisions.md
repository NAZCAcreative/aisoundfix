# Architecture & Design Decisions (ADR) — REFINERY

## 1. 디자인 결정 요약 (Design Decision Summary)
1. **오로라(Aurora) 브랜드 아이덴티티**: Suno AI 음원의 어둡고 뭉개진 소리가 맑은 빛으로 정제되는 순간을 시각화하기 위해 깊은 밤하늘(`#070B14`) 위 민트-바이올렛-핑크(`#5EEAD4`→`#818CF8`→`#F0ABFC`) 유영 애니메이션을 채택했습니다.
2. **단일 그라디언트 텍스트 클립 절제**: 히어로 헤드라인에만 `background-clip: text`를 단 1회 적용하여 시각적 몰입감과 정교한 브랜드 프리미엄 톤을 유지했습니다.
3. **오로라 오브(Aurora Orb) 진행률 시스템**: 원형 글로우 오브의 차오름과 3단 단계별 체크리스트를 연동해 지루한 진행률 바 대신 음질이 가시적으로 정제되는 경험을 제공합니다.
4. **위치 동기화 A/B 비교 오디오 플레이어**: 원본과 정제본 오디오 간 `currentTime`과 재생 상태를 100% 동기화하여 음질 개선 차이를 체감할 수 있게 설계했습니다.
5. **모바일 퍼스트 (360px) 최적화 & GPU 튜닝**: 모바일에서 블롭 크기와 `blur(40px)`를 조정하여 프레임 드랍을 방지하고 터치 타깃 44px 이상을 보장하였습니다.

## 2. 기술 스택 선택 이유
- **No-Build Vanilla Web Standard**: 외부 빌드 툴이나 JS 라이브러리 라이선스 이슈 없이 빠른 실행 속도와 안정성을 위해 순수 HTML5/CSS3/Vanilla JS를 선택.
- **Pure CSS Aurora**: Canvas/Image 자원 요청 없이 GPU 하드웨어 가속 기반 Pure CSS `@keyframes`와 `radial-gradient`로 오로라 유영 연출.
- **Web Audio API 데모 엔진**: DEMO 모드(`DEMO = true`)일 때 업로드 음원에 대해 BiquadFilter(Lowpass vs High Shelf & Compressor)를 적용하여 A/B 오디오 소리를 실제로 다르게 들려주는 실감 나는 데모 제공.

## 3. 사운드 랩 음향 설계와 검증 · 2026-11-21

현재 3008 스튜디오는 서버에서 보정한 24비트 PCM WAV를 브라우저에서 디코딩해 재생한다. 사운드 랩은 같은 트랙에서 음색을 바꾸는 세 가지 선택 효과를 제공한다. 기본값은 모두 0%다. ‘이 효과 듣기’는 복원 설정 위에서 실험 효과 하나를 재생한다. 스위치를 켜면 여러 효과를 함께 사용할 수 있다.

### 논문에서 채택한 원리

- **벨벳 룸**은 다크 벨벳 노이즈의 펄스 폭과 주파수 감쇠 관계를 활용한다. 직접 설계한 1.35초 임펄스 응답에서 약 18 ms 이후에 부호가 다른 펄스가 시작되고, 뒤로 갈수록 펄스 폭이 넓어진다. 좌우 시드를 고정해 반복 렌더가 재현된다. A/B의 길이를 맞추기 위해 곡 끝 25 ms에서 잔향만 페이드한다. [Fagerström 외, JAES 2024](https://research.aalto.fi/en/publications/non-exponential-reverberation-modeling-using-dark-velvet-noise/) · [Fagerström, Aalto 박사논문 2025](https://research.aalto.fi/en/publications/velvet-noise-in-audio-processing/)
- **고스트 베이스**는 저음의 상위 배음에서도 음정을 지각하는 원리를 활용한다. 중앙 신호의 32~65 Hz와 65~110 Hz를 따로 분석하고, 각 대역의 진폭을 따라가는 2·3차 배음을 원본에 더한다. 저음이 많은 화음에서는 합성 성분이 거칠게 들릴 수 있어 사용자가 혼합량을 선택한다. [Larsen과 Aarts, JAES 2002](https://aes.org/publications/elibrary/elibrary-page/?id=11088) · [가상 베이스 음색 및 왜곡 연구, AES 2015](https://aes.org/publications/elibrary/elibrary-page/?id=18050)
- **리듬 포커스**는 시간축·주파수축 17칸 중앙값과 소프트 마스크로 타악 성분을 강조한다. 마스크를 두 채널이 공유해 중심 위치를 유지하고, 블록 앞뒤에 문맥을 포함해 블록 경계에서 분석이 끊기지 않게 했다. 건반이나 기타의 첫 타격도 함께 강조될 수 있다. [FitzGerald, DAFx 2010](https://dafx10.iem.at/papers/DerryFitzGerald_DAFx10_P15.pdf)

### 측정

리듬 분리 → 가상 베이스 → 잔향 순서로 적용한 뒤 4배 오버샘플링으로 출력 피크를 점검한다. 출력 게인 조정이 필요하면 Δ 청취의 원본 참조에도 같은 계수를 적용한다. 필터를 모두 끈 0.99 진폭의 997 Hz 사인파에서 24비트 저장 후 최대 차이는 0.00000012 이하였다.

| 입력과 설정 | 관측값 |
| --- | --- |
| 55 Hz 사인파, 고스트 베이스 80% | 추가된 110 Hz와 165 Hz의 진폭은 각각 0.202와 0.074였다. 55 Hz 잔차는 0.00001 미만이었다. |
| 330 Hz 지속음에 짧은 잡음 타격을 더한 신호, 리듬 포커스 80% | 타격 구간과 지속 구간의 RMS 비가 8.9 dB에서 21.1 dB로 증가했다. |
| 48 kHz 스테레오 임펄스, 벨벳 룸 68% | 잔향 좌우 상관은 0.013이었다. 왼쪽 채널의 고역 대 중역 에너지비는 초기 −3.0 dB, 후기 −15.2 dB였다. |
| 24초 예제, 기본 청취 강도의 세 효과를 동시에 적용 | FFmpeg EBU R128 독립 측정은 −17.4 LUFS, −1.0 dBTP였다. 세 효과를 각각 적용한 결과와 조합 전체에서 스튜디오 표시와의 차이는 0.1 LU, 0.1 dB 이내였다. |

신호 회귀 검사는 프로젝트 루트에서 `python tests/test_sound_lab.py -v`로 재현할 수 있다. 통제된 청취자 선호도 시험과 실제 휴대전화 스피커별 평가는 별도 검증 과제다.

## 4. 압축 손상과 잘린 피크의 복원 실험 · 2026-11-22

### 기준 음원과 평가 방법

Apollo 저자들이 공개한 서로 다른 6초 스테레오 원본 15개를 사용했다. 모두 44.1 kHz 두 채널이며, 각 원본의 최대 샘플 진폭을 0.8로 맞췄다. 같은 구간마다 손상을 새로 만들고 미처리본을 포함한 모든 후보를 같은 타임라인에서 평가했다. 원본은 채점과 손상 생성에만 사용했다. 추가로 직접 합성한 8초 연주를 별도로 측정했다. 아래 집계는 공개 원본 15개 기준이다. 저자가 선택한 짧은 예제를 사용한 탐색 실험이며, 실제 이용자 업로드나 장르별 무작위 표본은 아직 평가하지 않았다. [저자 공개 음원](https://cslikai.cn/Apollo/) · [Apollo 논문](https://arxiv.org/abs/2409.08514)

- **파형 지표**는 두 채널에 하나의 전체 게인을 허용한 SI-SDR이다. 파형의 타이밍과 모양이 원본에 가까울수록 높다.
- **주파수 대역 오차**는 전체 RMS를 맞춘 뒤 80 Hz~20 kHz의 32개 ERB 간격 대역에서 구한 로그 에너지 차이의 제곱평균제곱근이다. 2048샘플 Hann 창, 1024샘플 간격, 기준 최대 대역 에너지 대비 −70 dB 바닥값을 사용했다. 기준 에너지가 가장 큰 프레임보다 40 dB 이상 조용한 프레임은 제외했다. 수치가 낮을수록 원본의 주파수 분포에 가깝다.
- **잘린 부분의 오차 감소**는 손상본과 복원본에서 실제로 잘렸던 샘플의 제곱오차 합을 비교한 값이다. 3 dB 감소는 그 부분의 오차 에너지가 약 절반이 됐다는 뜻이다.
- 표는 각 구간에서 미처리본 대비 변화를 먼저 구한 뒤 중앙값을 냈다. 양수는 각 지표의 개선을 뜻한다. 두 지표 동시 개선은 양쪽 모두 0.01 dB를 넘은 경우로 집계했다. 이 수치는 청취자가 알아챌 수 있는 차이를 뜻하지 않는다.

### 하드 클리핑

절댓값 상위 약 2%와 6%의 샘플을 각각 같은 높이에서 잘랐다. 실제 복원에는 그 비율이나 기준 음원을 전달하지 않았다. 새 방식은 입력에서 같은 높이로 평평해진 피크를 찾고, 2 ms 이하인 구간을 앞뒤 기울기로 보간한다. 좌우 채널의 관계가 구간 양쪽에서 일관되고 다른 채널의 피크가 온전하면 그 채널도 참고한다. 같은 파일에 관측 한계의 82%인 가상 한계를 만들고, 온전한 피크를 얼마나 잘 되살리는지로 구간 길이별 강도를 정한다. 학습용 구간에 실제 손실로 검출된 샘플이 하나라도 있으면 제외한다. 잘린 관측값만으로 복원을 학습하는 선행 연구가 있으며, 여기서는 이 국소 보간과 강도 추정 조합을 직접 구현했다. [Sechaud 외, EUSIPCO 2024](https://arxiv.org/abs/2409.15283) · [디클리핑 알고리즘 비교 연구](https://arxiv.org/abs/2007.07663)

| 방법 | 2% 손상 · 잘린 부분 오차 감소 | 6% 손상 · 잘린 부분 오차 감소 | 6% 손상 · 파형 지표 향상 | 6% 손상 · 대역 오차 감소 |
| --- | ---: | ---: | ---: | ---: |
| FFmpeg adeclip 기본값 | 2.85 dB | 2.35 dB | 1.57 dB | 0.74 dB |
| 앞뒤 기울기 보간 | 1.58 dB | 1.09 dB | 0.60 dB | 0.37 dB |
| 보간과 반대편 채널 추정 | 1.59 dB | 1.10 dB | 0.61 dB | 0.35 dB |
| 위 조합에 곡별 강도 추정 추가 | **2.97 dB** | **2.75 dB** | **2.53 dB** | 0.45 dB |

곡별 강도 추정은 두 손상 강도에서 각각 15개 모두 파형과 대역 오차가 개선됐다. 6% 조건에서는 FFmpeg의 대역 오차 개선 폭이 더 컸다. 별도 합성 연주의 잘린 부분에서 오차 감소는 각각 0.56 dB와 0.38 dB였다. 깨끗한 공개 원본 15개에 새 방식을 적용한 결과는 입력과 샘플 단위로 같았다. 다만 손상본에서 원래부터 절단 높이와 정확히 같았던 샘플도 평탄부로 판정할 수 있다. CSV의 `outside_max_delta`가 실제 손실 샘플 밖에서 생긴 가장 큰 차이를 기록한다. 클리핑 뒤 128 kbps MP3로 저장한 별도 대조군은 15개 모두 평탄부를 검출하지 못했다.

### 손실 압축

FFmpeg로 각 원본을 MP3 48·128 kbps와 AAC 목표 64 kbps로 인코딩했다. 45개 입력에서 기준과 대조한 타이밍 오프셋은 모두 0샘플이었다. 연구 당시 스튜디오 후보는 실제 업로드 분석 함수가 선택한 설정을 실제 렌더 함수에 전달했다. AAC의 스트림 비트레이트가 반올림 후 64 또는 65 kbps여서 15개 중 9개에만 당시 Apollo 추천이 적용됐다.

| 방법 | 48 kbps MP3 · 파형 향상 / 대역 오차 감소 | 128 kbps MP3 · 파형 향상 / 대역 오차 감소 | 목표 64 kbps AAC · 파형 향상 / 대역 오차 감소 |
| --- | ---: | ---: | ---: |
| 연구 당시 추천 | −3.21 / +7.63 dB | −5.22 / −0.19 dB | −4.30 / −0.04 dB |
| Apollo만 55% 혼합 | −3.00 / +7.54 dB | −8.18 / +0.84 dB | −4.53 / +0.25 dB |
| 감지한 고역 경계 위주로 Apollo 55% 혼합 | −0.12 / +6.24 dB | −0.005 / +1.37 dB | 0.00 / +0.43 dB |
| 관측 위상에서 대역 크기 보정 후 고역 12% 혼합 | +0.006 / +2.49 dB | −0.33 / +0.24 dB | −0.14 / −0.04 dB |
| 재압축 오차만으로 대역 크기 보정 | −0.06 / −0.01 dB | −0.16 / −0.07 dB | −0.006 / 약 0.00 dB |

첫 실험은 미처리, 연구 당시 추천, Apollo 55%·100%, 6 kHz 위주 혼합, 감지한 대역 위주 혼합을 대조했다. 대역 경계는 입력의 주파수별 에너지 급락을 찾은 값이다. 검출된 주파수의 90%를 차단 주파수로 삼아 모델의 변화분에 4차 고역 통과 필터를 앞뒤 방향으로 적용했다. 의도적으로 8 kHz 저역 통과 필터를 건 대조군도 15개 모두 경계가 검출됐다. 경계만으로는 압축 손상과 제작 의도를 구분할 수 없다. [대역 제한이 알려지지 않은 음원 복원 연구](https://arxiv.org/abs/2306.01433)

후속 실험은 같은 구간을 다시 사용했다. 관측된 시간·주파수 성분의 위상을 유지하면서 Apollo의 크기 추정만 일부 반영하고, 별도로 사라진 고역을 소량 더했다. 다른 후보는 같은 코덱으로 두 번 더 압축한 세대 간 크기 차이에서 대역별 계수를 추정했다. 48 kbps MP3에서 전자의 두 지표가 동시에 0.01 dB 넘게 개선된 구간은 6/15였다. 두 지표에 0.1 dB 기준을 적용하면 3/15였다. 재압축만으로 보정한 방법은 어느 압축 조건에서도 일관된 개선을 보이지 않았다.

### 청음과 재현

스튜디오는 무손실 입력에서 복원할 피크가 확인되면 곡별 보정을 기본 적용하고, 보정 에너지가 가장 큰 최대 6초를 반복 재생한다. 48 kbps MP3에서 고역 경계가 검출되면 관측 위상에서 대역 크기를 보정하고 고역 변화분을 12% 섞는 후보를 선택할 수 있다. 그 밖의 입력은 수동 필터를 끈 상태로 연다. 연구 스크립트의 `current`는 당시 기본 프리셋으로 고정했다. 블라인드 청음은 별도 제작한 합성 연주의 기준 원본과 후보를 무작위 순서로 제시한다. 모든 파일은 44.1 kHz 스테레오 24비트 FLAC이며 그룹별 음량을 맞췄다. 웹 화면의 선택은 현재 브라우저에서만 표시한다. 정식 청취자 패널을 모집해 측정한 선호도는 없다. [로컬 블라인드 청음](http://localhost:3008/research/restoration/) · [ITU-R BS.1534 청취 평가 방법](https://www.itu.int/rec/R-REC-BS.1534/en)

프로젝트 가상환경과 기존 Apollo 체크포인트를 사용한다. 실험 장비는 RTX 5070 Ti이고 PyTorch 2.11.0+cu128, SciPy 1.17.1, FFmpeg gd3ad8a7fee, Apollo 체크포인트 리비전 `c68bd80fdd9c0d93d2f4a833cb154624f660a561`에서 측정했다.
